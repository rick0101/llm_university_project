# A Comprehensive Survey on Security Challenges in Large Language Models

*Version 1.0 — July 2026*

---

## Abstract

Large language models (LLMs) have become integral to modern software-development workflows, automating tasks from code generation to bug detection with human-competitive performance. However, this rapid integration into critical applications introduces substantial security vulnerabilities, as the instruction-following capability that enables flexibility also exposes models to attacks capable of corrupting outputs, exfiltrating data, and compromising downstream systems. This survey presents a systematic literature review of the emerging field of LLM security, synthesizing findings from 117 cited sources after a primary-source attribution audit across the principal threat categories: adversarial attacks, data and model poisoning, prompt injection, and hallucination-induced integrity failures. We organize the landscape into a taxonomy spanning training-time and inference-time threats, analyzing mechanisms ranging from backdoor poisoning and jailbreak exploits to multi-turn conversational manipulation and automated red-teaming frameworks. The survey further examines the critical reconceptualization of hallucination—long treated as an accuracy problem—as a serious security vulnerability enabling misinformation and unsafe automated decision-making. Beyond threat characterization, we provide a comprehensive analysis of cross-cutting defense strategies, including alignment hardening, adversarial training, input/output sanitization, and defense-in-depth architectures, alongside a consolidated evaluation framework detailing standardized benchmarks, metrics, and testing methodologies for reproducible security assessment. Our synthesis reveals that while the field has made significant progress—with adversarial fine-tuning reducing attack success rates on some models—larger, more flexible architectures remain disproportionately vulnerable, and defenses remain fragmented across isolated attack vectors rather than offering holistic resilience. We conclude by identifying critical open challenges, including the poisoning impasse in certified defenses and the need for unified security frameworks, proposing directions for future research toward robust and trustworthy LLM deployment.

## Introduction

Code-oriented LLMs are now central to modern software-development workflows, automating tasks such as function implementation, bug detection, and unit-test generation with performance that rivals human developers [Mo_2025_LLMs_eccb86af]. This rapid integration into critical applications introduces substantial security vulnerabilities, as the instruction-following capability that enables flexible functionality also exposes models to a spectrum of attacks that can corrupt outputs, exfiltrate sensitive data, and compromise downstream systems. This survey systematically organizes the LLM security landscape into four principal threat categories: (i) inference-time adversarial attacks, (ii) data and model poisoning during training, (iii) prompt injection, and (iv) hallucinations.

#### Adversarial Attacks (Inference-Time)
Adversarial attacks at inference time manipulate LLM outputs through carefully crafted inputs that bypass safety guardrails or induce unintended behavior. Even well-aligned models remain susceptible to jailbreak attacks, where adversarial prompts circumvent built-in safety mechanisms [Zhao_2025_LLM_45bb4e13]. In the code domain, adversarial prompts and deliberately constructed code‑completion inputs can readily cause LLMs to generate vulnerable or insecure code [Mo_2025_LLMs_eccb86af]. These attacks highlight the brittleness of code LLMs to adversarial input manipulation and underscore the need for robust test-time defenses.

#### Data and Model Poisoning
Training-time data poisoning injects malicious behavior into LLMs during pre‑training, fine‑tuning, or alignment phases. LLMs are susceptible to data poisoning during supervised fine‑tuning and preference alignment stages such as RLHF and DPO [Kusaka_2025_LLM_b1b5bb78]. Backdoor poisoning attacks, a subclass of data poisoning, embed triggers into training corpora so that the model behaves normally on clean inputs but produces attacker‑desired outputs when a specific trigger appears, remaining covert under standard evaluation protocols [Souly_2025_LLMs_4e3c2e97]. Recent evidence shows that poisoning does not require proportional attack effort: as few as 250 poisoned documents can compromise models across a wide range of sizes, demonstrating that larger models are not inherently more resilient [Souly_2025_LLMs_4e3c2e97]. Weight-level backdoors, injectable with limited resources, further illustrate that the attack surface extends to the model’s internal parameters [Li_2024_Badedit_b5ba8f82]. LLM providers that expose fine‑tuning APIs face additional risk: an adversary with fine‑tuning access can bypass safeguards or introduce misalignment even with seemingly innocuous datasets [Egler_2025_Detecting_6f5c47ea]. These vulnerabilities underscore the necessity of defense strategies that span the entire LLM lifecycle.

#### Prompt Injection
Prompt injection attacks exploit the LLM’s inability to distinguish trusted system instructions from untrusted data, causing the model to follow injected directives [Wu_2025_LLM_7fee400f]. Direct prompt injection occurs when a malicious attacker manipulates the user query to an LLM, causing the model to generate outputs that deviate from predefined instructions [Wu_2025_LLM_7fee400f]. Indirect prompt injection occurs when third-party data input contains instructions that the LLM should never follow; such payloads are embedded in external sources—web pages, search results, or database entries—that the model later retrieves and processes [Wu_2025_LLM_7fee400f, Yao_2025_LLM_a1c8adc0]. Attackers have further refined these techniques into multi‑turn strategies, where the harmful payload is split across several conversational exchanges to evade detection [Shih_2025_AI_0f3eb425]. The threat is especially acute in long‑context settings where injected instructions constitute a small fraction of the input and are difficult to identify [Geng_2025_LLMs_16cfd21e]. LLM‑powered agents that autonomously interact with tools and APIs magnify the risk: indirect injection can lead to unauthorized data disclosure, execution of unsafe function calls, or manipulation of agent behavior [Chang_2025_LLM_1f6233a6]. In response, structure‑based methods such as StruQ, task‑specific fine‑tuning approaches like Jatmo, and preference‑based techniques like SecAlign have each reduced prompt-injection success while preserving model utility [Chen_2024_StruQ, Piet_2023_Jatmo, Chen_2024_SecAlign]. Training‑free defenses that repurpose the LLM itself to detect and remove injected content, as exemplified by PromptArmor, offer a flexible complement to training‑time interventions [Shi_2025_Promptarmor_d535ddee].

#### Hallucinations
Hallucinations, defined as the generation of plausible but factually incorrect or unsupported content, constitute a distinct trust and reliability challenge. While this survey does not identify specific adversarial hallucination attacks due to the absence of whitelisted sources on hallucination as an attack vector in the current corpus, the phenomenon is included as a fourth category to provide a comprehensive view of LLM security and safety risks.

Despite a rapidly growing body of individual studies, no prior comprehensive survey has systematically synthesized the intersecting challenges of LLM security, code intelligence, and hallucination phenomena across the critical period 2023–2026. This paper fills that gap by presenting a structured, temporally‑aware analysis of 299 papers published during this time frame. The synthesis traces the evolution of attack methodologies—from early heuristic prompt engineering to sophisticated gradient‑based injection and multi‑turn strategies—maps the emergence of evaluation benchmarks, and charts the progression of defense strategies across all four threat categories. By doing so, we provide the first holistic view of the LLM security landscape, highlighting how adversarial techniques have matured, how new attack surfaces have arisen with agentic deployments, and how defensive research has responded with prevention‑based and detection‑based countermeasures.

The remainder of this paper is organized as follows. Section 2 provides necessary background on LLM architectures, training paradigms, and threat models. Sections 3 through 6 examine each threat category in depth: Adversarial Attacks (Section 3), Data and Model Poisoning (Section 4), Prompt Injection (Section 5), and Hallucinations (Section 6). Section 7 surveys defense mechanisms, classifying them into prevention‑based and detection‑based approaches and discussing their trade‑offs. Section 8 presents a chronological synthesis of attack evolution, benchmark development, and landmark results. Finally, Section 9 identifies open challenges and outlines promising directions for future research.

Beyond the four categories enumerated above, the security challenge is compounded by the multi-stakeholder structure of modern LLM products, which typically comprise an application provider, a primary user, and third-party data sources; conflicts between the hierarchical instructions assigned to each stakeholder create the vulnerabilities exploited by prompt-injection attacks [Wu_2025_LLM_7fee400f]. The resulting threat surface is inherently multifaceted, spanning jailbreaks, prompt injections, and data poisoning, and is further complicated by the integration of text, image, and speech modalities. In high-stakes deployment domains—public discourse, education, healthcare, and law—the risks are particularly acute because models are trained on vast and often uncurated corpora. Code models face an even more concrete exposure: as early as 2023, Improta et al. [Improta_2023_AI_20bc1909] identified a novel data poisoning attack in which an attacker corrupts the training data of AI code generators to induce the generation of vulnerable code. Established taxonomies categorize these threats into jailbreaks, prompt injection, and data poisoning, although the boundaries between categories remain disputed [Li_2025_LLM_6131fb27].


## Background and Preliminaries

#### LLM Fundamentals and Training Paradigms

Large language models (LLMs) are generative models trained on massive text corpora to produce fluent, contextually coherent responses. Their development follows a multi-stage training pipeline: pre-training on broad web-scale data, supervised fine‑tuning (SFT) on instruction‑following tasks, and alignment via reinforcement learning from human feedback (RLHF) or direct preference optimization (DPO) [Kusaka_2025_LLM_b1b5bb78].

Safety alignment aims to make models reject harmful requests while preserving useful behavior. Evidence from primary studies shows that this alignment can be shallow, concentrated in the first few generated tokens [Qi_2025_ShallowAlignment]; can be weakened by even benign downstream fine‑tuning [Qi_2024_FineTuningSafety]; and can fail when decoding parameters are manipulated [Huang_2024_GenerationExploitation]. Krau et al. further model refusal behavior itself as a triggerable mechanism and propose targeted pruning to remove alignment [Krau_2025_LLM_ba659fee]. (The retrieved literature does not provide detailed expositions of Transformer architectures or mixture‑of‑experts designs; these well‑known foundations underpin modern LLMs but lie outside the security‑focused papers reviewed here.)

#### Safety Alignment and Its Vulnerability to Jailbreak Attacks

Safety alignment is intended to produce models that reject harmful requests, but dedicated red‑teaming methods can systematically circumvent these safeguards. A jailbreak attack is an adversarial prompt crafted to bypass the model’s built‑in safety mechanisms and elicit a harmful output [Kim_2025_LLM_2523db75, Ying_2024_Jailbreak_1125d3ba]. Automated jailbreak methods such as GCG and AutoDAN automatically search for prompts that bypass alignment [Zou_2023_Universal_ab8745c2, Liu_2024_AutoDAN_1d6cff47]. Optimization‑based attacks search for adversarial suffixes—short token sequences appended to a harmful query—that maximize the attack success rate (ASR) [Zheng_2024_Improved_67ad35e0]. ASR is defined as the percentage of queries that elicit an unsafe response, as measured by an independent safety classifier [Dang_2025_Rainbowplus_b158c5a2]. Beyond simple unsafe‑response classification, HarmBench standardizes automated red‑team evaluation, while StrongREJECT scores the harmfulness and specificity of jailbreak outputs [Mazeika_2024_HarmBench, Souly_2024_StrongREJECT]. Although effective against aligned LLMs, adversarial suffixes generated by these methods typically lack semantic meaning and exhibit high perplexity, making them susceptible to perplexity‑based defenses [Zheng_2024_Improved_67ad35e0]. In contrast, LLM‑assisted attacks employ auxiliary language models to generate semantically coherent adversarial requests that can bypass such filters, though they occasionally achieve lower ASR on strongly aligned models [Zheng_2024_Improved_67ad35e0]. Red teaming, both manual and automated, is essential for stress-testing alignment; manual red teaming uncovers nuanced vulnerabilities but is costly, driving the adoption of automated approaches that leverage adversarial attacks and benchmarks. Jailbreak techniques can also transfer across models, amplifying the risk of widespread exploitation. The existence of robust, automated jailbreaks underscores the brittleness of current alignment approaches.

#### Prompt Injection: Direct and Indirect

Complementary to jailbreak, prompt injection attacks aim to modify model behavior by inserting malicious instructions into the input. Two primary modalities are distinguished:

- **Direct prompt injection**: the adversary, who is also the user, directly inserts malicious instructions into the prompt to coerce the model into performing unintended actions, such as extracting system prompts [Chen_2025_Indirect_11771399]. Classic examples include appending commands such as “Ignore previous instructions” or using role‑playing and obfuscation techniques [Ivry_2025_Sentinel_a518d27a]. This can lead to the generation of malicious content, leakage of private information, or execution of unauthorized actions [Wang_2024_LLMs_a70eec1a]. System prompt extraction has been demonstrated through manually crafted queries, gradient-based optimization, and multi-turn prompting techniques [Das_2025_System_cda316c4].
- **Indirect prompt injection**: For indirect prompt injection, attackers inject malicious instructions within external data sources, such as web documents, which are later retrieved by LLMs using external tools [Chen_2025_Indirect_11771399]. The LLM then executes the injected instructions, resulting in unintended responses [Chen_2025_Indirect_11771399].

The emergence of RAG and LLM‑based agents has amplified the attack surface, as demonstrated by indirect jailbreak methods that poison an external knowledge base to force the model to produce malicious dialogues [Wang_2024_LLMs_a70eec1a].

#### Data Poisoning and Backdoor Attacks

Data poisoning attacks modify the training dataset to induce undesired behaviours or embed backdoor triggers [Kusaka_2025_LLM_b1b5bb78]. LLMs are susceptible to data poisoning due to their multistage training pipeline, which exposes multiple points for injection, including the SFT and the RLHF/DPO alignment phases [Kusaka_2025_LLM_b1b5bb78]. A backdoor attack is a subclass of data poisoning in which the model behaves normally on clean inputs but exhibits attacker‑specified behavior when a secret trigger pattern appears in the input [Li_2024_Badedit_b5ba8f82, Souly_2025_LLMs_4e3c2e97]. Existing data‑poisoning‑based backdoor attacks on LLMs typically require access to the full training set and substantial computational resources, reflecting a white‑box setting [Li_2024_Badedit_b5ba8f82]. Despite empirical demonstrations of vulnerabilities in both the SFT and alignment phases, the theoretical foundations of poisoning attacks in the RLHF/DPO stage remain largely unexplored [Kusaka_2025_LLM_b1b5bb78].  For backdoor attacks on LLM-based agents, the Attack Success Rate (ASR) measures the probability of executing the attacker’s intended malicious operations, while the Follow Step Ratio (FSR) evaluates stealthiness by measuring the rate at which the agent still correctly performs benign operations [Wang_2024_LLM_7c0f7746].

#### Threat Model Taxonomy

The attacks described above can be organized along several axes.

- **Training‑time vs. inference‑time**: Data poisoning and backdoor attacks are training‑time threats that corrupt the model before it is served [Souly_2025_LLMs_4e3c2e97]. In contrast, prompt injection and jailbreak attacks are inference‑time threats, executed against a deployed model through crafted inputs [Kim_2025_LLM_2523db75].
- **White‑box vs. black‑box access**: White‑box adversaries possess full knowledge of the model’s internals and training data; data poisoning attacks that require access to the entire training pipeline fall into this category [Li_2024_Badedit_b5ba8f82]. Black‑box adversaries, by contrast, interact only through the model’s input–output interface, as is typical for jailbreak and prompt injection attacks where no internal parameters are needed [Kim_2025_LLM_2523db75].
- **Attacker goals**: The objectives are diverse. **Model corruption** aims to implant a backdoor or degrade overall accuracy [Souly_2025_LLMs_4e3c2e97]. **Policy bypass** seeks to circumvent safety alignment and induce the model to generate harmful content, a central objective of jailbreak attacks [Kim_2025_LLM_2523db75]. **Instruction manipulation** targets the execution of attacker‑specified commands, as in prompt injection, potentially leading to unauthorized actions or data disclosure [Zhang_2025_AI_647785c1]. **Privacy leakage** targets the extraction of private data, such as personal information or system prompts [Wang_2024_LLMs_a70eec1a].

#### Security Relevance in Code Intelligence and General NLP

LLMs have become integral to natural language processing tasks such as summarization and instruction following [Kim_2025_LLM_2523db75], and increasingly serve as code assistants. Standard alignment datasets consist almost exclusively of natural language instructions and lack malicious code samples; consequently, models lack the ability to recognize and reject malicious code payloads [Chen_2024_Rmcbench_19963c81]. Benchmarks like RMCBench have been proposed to remedy this gap and improve models’ resilience to code‑level threats [Chen_2024_Rmcbench_19963c81]. Integration into retrieval-augmented generation pipelines exposes LLMs to indirect prompt injection through poisoned external documents [Chen_2025_Indirect_11771399]. The phenomenon of hallucination—generation of factually incorrect content—is another important safety concern recognized in the broader literature, but it is not addressed by the security‑focused papers retrieved for this survey.

Safety alignment builds on a standard multi-stage recipe. In the first stage of the RLHF pipeline, a pre-trained generative model is fine-tuned with a cross-entropy objective to predict the next token on instruction-following, summarization, or question-answering data [Baumgartner_2024_RLHF_f07e5209].  The reliance on human preferences creates an additional attack surface: an adversary can synthesize preference data to steer an RLHF/DPO learner toward a target policy, and recent theory quantifies the number of poisoned examples required when preference datasets are constructed from scratch or augmented [Nika_2025_Policy_b88b7229]. Synthetic data and self-play mechanisms have also been proposed to reduce annotation cost [Wu_2026_Self_ae7eafa5]. In parallel, defenses built directly on top of alignment aim to mitigate jailbreaks; adversarial training offers a decent robustness–utility balance but requires large-scale execution [Kumar_2024_LLMs_67538c80].

The threat model is further refined by distinguishing levels of adversary knowledge. Gray-box attackers may exploit partial knowledge such as the training framework, approximate architecture, or data distribution [Pathade_2026_AI_d9f29391]. Adversary knowledge can also be classified as training-time, inference-time, or platform-specific [Pathade_2026_AI_d9f29391]. Taxonomy boundaries between categories such as jailbreaks and prompt injection remain disputed [Li_2025_LLM_6131fb27]. In agentic systems, backdoors can target intermediate reasoning or action steps, not only final outputs, making poisoning more concealed [Yang_2024_LLM_eba70536]. Backdoors can enter at multiple training stages, while federated learning adds poisoning vectors through malicious clients [Mamun_2025_LLMs_7b0b92b0].


## Training-Time Threats: Data Poisoning and Backdoor Attacks

Large language models are routinely exposed to vast amounts of untrusted data—particularly during pre‑training—and this exposure creates a broad attack surface for data manipulation [Souly_2025_LLMs_4e3c2e97]. Training-time threats exploit this surface to implant hidden behaviours, most commonly through backdoor poisoning: an attacker associates a specific trigger with a malicious output during training. When the model later encounters the trigger at inference, it produces attacker-chosen outputs while maintaining normal performance on clean inputs [Souly_2025_LLMs_4e3c2e97, Li_2024_Badedit_b5ba8f82]. The stealthy nature of these attacks—the fact that standard evaluation protocols often miss the backdoor—makes them particularly dangerous [Souly_2025_LLMs_4e3c2e97]. This section traces the evolution of training‑time threats from early demonstrations of low‑data backdoor injection through modern alignment poisoning, supply‑chain vulnerabilities, and the emerging defences that aim to detect, remove, or formally certify against such attacks.

#### Attack Vectors and Minimal Data Requirements

Early work established that a tiny fraction of poisoned examples can compromise a model. BadEdit demonstrated that even highly constrained adversaries—limited in data, time, and compute—could implant effective backdoors into LLMs [Li_2024_Badedit_b5ba8f82]. The threat was further underscored by Souly et al., who formalized the backdoor poisoning threat model, assuming an attacker can arbitrarily modify a fixed number of training examples with the goal of keeping the backdoor covert [Souly_2025_LLMs_4e3c2e97]. In this threat model, the attacker aims for high attack success when the trigger is present while preserving normal behaviour on clean inputs, making the poison especially insidious.

Conventional poisoning attacks have concentrated on the post‑training stages because the exorbitant cost of poisoning pre‑training data—often scraped from the web—has historically reduced its appeal. Existing research focuses on instruction tuning (a form of supervised fine‑tuning) and reinforcement learning from human feedback [Zhang_2024_LLMs_6cc321bf]. Nevertheless, pre‑training‑time poisoning remains a realistic concern: Carlini et al. estimated that an attacker could control at least 0.01% of major web-scale training datasets for roughly USD 60, while purchasing expired domains could give control over at least 0.01% of each dataset for USD 1,000 [Carlini_2024_WebScalePoisoning]. 

A particularly worrying finding is that backdoors implanted during pre‑training can survive later alignment [Zhang_2024_LLMs_6cc321bf]. Hubinger et al. directly demonstrated “sleeper agents” whose deceptive behavior persisted through supervised fine‑tuning, reinforcement learning, and adversarial training [Hubinger_2024_SleeperAgents].

The drive toward automation has expanded the attacker’s capabilities significantly. In parallel, automated red-teaming frameworks like AUTOBACKDOOR leverage LLM-based agents to generate context-aware triggers and poisoned responses without human intervention, making backdoor data generation scalable and highly effective across diverse tasks and models [Li_2025_LLM_29a3a9ff]. Such frameworks lower the barrier for attackers and simultaneously make the poisoned data harder to detect because the triggers are crafted to blend naturally into the training distribution. This shift toward agent‑driven poisoning marks a qualitative escalation in the threat landscape.

#### Alignment Poisoning

As alignment with human preferences has become standard through reinforcement learning from human feedback (RLHF) and direct preference optimization (DPO), adversaries have turned their attention to the preference datasets that govern this final stage. Baumgärtner et al. demonstrated that injecting as little as 1–5 % of poisonous preference pairs into the reward‑model training data can reliably manipulate the final language model to generate a target entity in a target sentiment [Baumgartner_2024_RLHF_f07e5209]. They proposed concrete poisoning strategies—building pairs by asking a generative oracle for high‑quality responses with the desired sentiment, and mixing selected pairs into the training set—that require very few malicious samples yet produce consistent misbehaviour. Preference feedback is inherently subjective, so poisoned annotations are difficult to detect during data auditing; moreover, because RLHF is the last alignment step, a backdoor embedded there is more persistent than one introduced during earlier SFT [Duan_2025_RLHF_88790599].

A spectrum of empirical attacks has been proposed. RankPoison flips selected preference labels to make an RLHF-trained model generate longer outputs, including a backdoor setting activated by a trigger word, while preserving non-targeted safety behavior [Wang_2024_RLHFPoison]. Other work targets the RLHF reward model directly by manipulating preference scores, enabling adversaries to misguide alignment without altering the primary training data [Duan_2025_RLHF_88790599]. Duan et al. exploited two complementary vectors: a semantic‑level poisoning that establishes cross‑modal associations and a feature‑level poisoning enhanced by feature collision to remain stealthy [Duan_2025_RLHF_88790599]. Dutta et al. extended these ideas with Erinyes, a framework that constructs emotion-aware triggers (specifically angry emotions) and a selection scheme that achieves generalization to unseen prompts under low poisoning budgets, thus revealing that emotion synthesis can create generalizable backdoors in RLHF [Dutta_2025_RLHF_dbbb4564]. This work demonstrates that even subtle, affect‑based perturbations can serve as effective triggers.

On the theoretical side, Kusaka et al. underscored that the multistage training pipeline—pretraining, supervised fine‑tuning, and RLHF/DPO—makes LLMs susceptible to poisoning at multiple points. They derived upper and lower bounds on the number of label flips required to steer the policy toward an attacker-chosen target without altering the compared outputs, and proposed a post-processing method that reduces the cost of existing label-flipping attacks [Kusaka_2025_LLM_b1b5bb78]. In a complementary study, Nika et al. examined the inherent robustness of RLHF and DPO against structured data augmentation attacks from a theoretical perspective, showing how these paradigms compare in susceptibility—a foundational step toward understanding worst-case vulnerabilities [Nika_2025_Policy_b88b7229]. Their analysis, framed as an attacker aiming to enforce a target policy through synthesized preference data, provides sample‑complexity bounds that characterize when RLHF and DPO differ in robustness. Together, these empirical and theoretical studies establish that the alignment process is exquisitely sensitive to a small number of poisoned preferences.

#### Supply‑Chain and Federated Threats

Attacks need not always penetrate the primary training pipeline; they can enter through the supply chain of fine‑tuned adapters and model merging practices. Model merging, which combines multiple domain‑specific models into a single versatile model, creates a natural vector for backdoor injection. Yin et al. discovered that existing backdoor attacks become ineffective when the attacker is constrained to use Low‑Rank Adaptation (LoRA) for fine‑tuning due to limited computational resources, because the low‑rank update space weakens the malicious signal. To overcome this, they introduced LoBAM, a method that strategically fuses a malicious LoRA-adapted model with a benign one in a way that amplifies the attack-relevant components while preserving stealth [Yin_2024_LoRA_90edff2c]. LoBAM achieved over 98% attack success rate under both on-task and off-task settings on benchmark image datasets (e.g., CIFAR-100) when merged with multiple standard strategies, significantly outperforming prior merging attacks and remaining undetectable by conventional detection methods [Yin_2024_LoRA_90edff2c]. These results illustrate that low‑resource fine‑tuning does not eliminate supply‑chain risk; rather, it compels the community to design detection and defence mechanisms tailored to the model‑merging context.

Federated learning (FL) introduces a similar threat, where malicious clients can poison their local copies of a shared model before aggregation. Attacks in FL settings leverage compromised foundation models to generate synthetic data embedded with triggers, causing the aggregated model to misclassify toward an attacker-chosen output [Mamun_2025_LLMs_7b0b92b0]. Because the central server does not inspect each client’s data, such poisoned updates can slip through and contaminate the global model, highlighting the need for robust aggregation and verification protocols that are still in early stages of development.

#### Defenses and Certification

Defending against data poisoning has progressed along several axes: detection and sanitization, corrective training, and formal certification. One of the earliest and most widely studied detection paradigms is the spectral-signature defence, which assumes that poisoned samples induce anomalous internal representations. It computes outlier scores from the correlation of centered representations with dominant singular vectors and removes high-scoring samples before retraining [Tran_2018_SpectralSignatures]. Yan et al. later evaluated representation-based variants for poisoned language models, including clustering over principal components [Yan_2024_LLM_694cf462].

However, the standard spectral‑signature configuration, inherited from computer vision, is often suboptimal for code models. Le et al. performed an exhaustive evaluation across 252 experimental combinations involving modern code models (CodeBERT, CodeT5) and attack strategies (fixed, grammatical, adaptive triggers) and discovered a new proxy metric that accurately estimates the actual performance of spectral signatures without requiring model retraining after defense [Le_2025_Signature_fc7a3218]. This finding enables practitioners to tune the defence correctly—choosing the right number of singular vectors, outlier threshold, and layer from which to extract representations—and greatly improves the reliability of spectral signatures in code security.

Rather than detecting poisoned data, a new family of corrective defences aims to neutralise backdoors already present in the model. Kim et al. proposed MB-Defense, a two-component training framework that merges attacker and defender triggers into a unified backdoor representation and then breaks this representation to restore clean behavior [Kim_2026_Merging_5ef69cbf]. Remarkably, MB-Defense requires only a small number of clean samples (e.g., 128) to achieve effective mitigation, making it practical for instruction-tuned LLMs [Kim_2026_Merging_5ef69cbf]. This “defensive poisoning” followed by neutralisation represents a pragmatic strategy that leverages the poisoning mechanism to immunize the model.

Formal guarantees against poisoning have been scarce, but Lorenz et al. introduced FullCert, which marks a significant advance. FullCert is the first certifier that jointly computes sound, deterministic bounds against both training-time and inference-time attacks, addressing the end-to-end robustness problem [Lorenz_2024_Fullcert_7dbc4820]. Its theoretical analysis provides soundness and convergence guarantees, and the accompanying open-source library BoundFlow enables experimental evaluation [Lorenz_2024_Fullcert_7dbc4820]. FullCert unrolls the entire training and inference into a single computation graph and uses interval‑bound abstract interpretation to bound the effect of both poisoned training data and adversarial test inputs. While the current computational cost restricts FullCert to small models, the framework establishes a principled direction for proving worst‑case poisoning resilience.

An unexpected form of robustness has been observed in reasoning‑augmented models. Foerster et al. studied decomposed reasoning poisons that alter only the chain‑of‑thought while leaving the prompt and final answer clean. They found that, although such poisons can be injected, reliably activating them to change final answers is surprisingly difficult because the models often recover from backdoors activated within their thought processes [Foerster_2025_Reasoning_70422133]. This resilience appears to stem from the architectural separation between reasoning and final answer generation, suggesting a natural damping of backdoor effects that may grow as models become more capable.

Despite these advances, the arms race continues. AUTOBACKDOOR produces stealthy, scalable poisoned data through autonomous agent-based reasoning, and experimental results indicate that existing defense techniques struggle to detect or mitigate these attacks, underscoring the urgent need for agent-aware defenses that can keep pace with the next generation of poisoning strategies [Li_2025_LLM_29a3a9ff]. The convergence of low‑data poisoning, supply‑chain vectors, and automated attack generation demands a multi‑layered defence that combines detection, neutralisation, and formal certification—an area where substantial work remains.

#### Chat Templates as a Supply-Chain Vector

The supply chain for chat-optimized LLMs includes not only pretrained weights and tokenizer vocabularies but also the chat templates that structure multi-turn dialogues. In practice, the chat template is usually distributed alongside the tokenizer and model parameters as part of the model package, and the widespread adoption of these templates has introduced new attack surfaces whose security implications remain largely unexplored [Wang_2026_Badtemplate_5224c909]. BadTemplate demonstrates this risk concretely: instead of modifying parameters through poisoned datasets and fine-tuning with explicit triggers, it embeds the backdoor instruction into a high-priority system prompt, outperforming prior prompt-based methods while requiring no parameter updates [Wang_2026_Badtemplate_5224c909]. The attack is therefore lightweight and well suited to resource-constrained or access-limited settings where model editing and fine-tuning are unavailable [Wang_2026_Badtemplate_5224c909]. This suggests that auditing model packages for malicious templates is as important as inspecting training corpora.

#### Detecting Backdoors in Code Models

Code models have also motivated specialized defenses. CODEPURIFY compares against spectral signatures, activation clustering, ONION, and OSeqL, then uses masked-code purification and model predictions to identify and neutralize suspicious trigger regions [Mu_2024_Codepurify_c5777b0e]. This diversity reflects the difficulty of sanitizing code without sacrificing functional correctness.

#### Low-Resource Adversaries and Federated LoRA Sharing

A complementary threat arises from low-resource adversaries who cannot fully fine-tune modern LLMs. In the threat model used by Mamun et al., the adversary has only enough hardware to train LoRA adapters and augments roughly 1.5k task-irrelevant attack examples generated through a proprietary LLM, together with around 8.5k public instruction-following examples. These adapters can then be uploaded to open platforms such as HuggingFace, expanding the pool of potential victims. The same framework extends to federated learning, where each client sends only LoRA parameter updates to a central server for aggregation over non-IID local data. This modest computational requirement keeps the attack cost low, so any actor with suitable GPUs can craft and distribute poisoned adapters [Mamun_2025_LLMs_7b0b92b0].

#### Backdoors in LLM-Based Agents

Training-time threats also extend to LLM-based agents, whose multi-step reasoning and environment interaction create attack surfaces beyond conventional input prompts. Zhu et al. identify query-attack, observation-attack, and thought-attack as agent-specific backdoor vectors [Zhu_2025_LLM_dd9cc851]. Prior agent attacks, however, often lack stealth and can be exposed by memory audits; to overcome this, Zhu et al. proposed a dynamically encrypted multi-backdoor implantation attack that is both stealthy and adaptive [Zhu_2025_LLM_dd9cc851]. As agents become more capable, the notion of a trigger must accordingly expand to include observations, intermediate thought traces, and tool interactions, not only the raw input text.

Taken together, these emerging vectors—malicious chat templates, code-specific backdoors, low-cost LoRA distribution, and agentic triggers—underscore that training-time security cannot be reduced to dataset screening alone.


## Inference-Time Threats: Adversarial Attacks, Jailbreaks, and Prompt Injection

The deployment of large language models (LLMs) in safety‑critical applications has exposed a broad attack surface at inference time. Adversaries can craft inputs that cause the model to violate its intended behavioral constraints—ranging from adversarial perturbations that degrade output quality to jailbreaks and prompt injections that elicit explicitly harmful content. This section surveys the major classes of inference‑time threats, organized into five subsections: (1) adversarial perturbations on inputs, (2) methods that subvert safety alignment through jailbreaking, (3) indirect and multi‑turn prompt injection, (4) code‑driven attacks that conceal malicious intent, and (5) detection and mitigation strategies.

#### 1. Adversarial Perturbations on Inputs

Adversarial perturbations are modifications to inputs that cause machine‑learning models to produce incorrect or unexpected outputs while often preserving human‑perceived semantics. In the natural language processing domain, generating meaningful semantic‑preserving perturbations is challenging due to the discrete nature of text. For code inputs, techniques such as identifier substitution can degrade model output while maintaining syntactic correctness; however, the citable literature retrieved for this survey does not contain recent studies on semantic‑preserving adversarial perturbations on code or language. The discussion therefore focuses on the extensively studied adversarial‑suffix perturbations that power the majority of jailbreak attacks. These gradient‑based perturbations do not preserve the original semantics; instead they append optimized, often unintelligible token sequences—adversarial suffixes—that force the model to produce a desired harmful outcome, and they form the technical core of the jailbreak methods described in the next subsection.

The Greedy Coordinate Gradient (GCG) attack, introduced by Zou et al. in 2023, appends an adversarial suffix and optimizes it with a combined greedy and gradient-based search [Zou_2023_Universal_ab8745c2]. At each step, GCG identifies promising token substitutions from the negative gradient, samples a batch of candidates, evaluates their autoregressive losses, and retains the lowest-loss replacement; for universal and transferable attacks, it aggregates gradients and losses across multiple behaviors and models [Zou_2023_Universal_ab8745c2]. Because this objective does not optimize linguistic naturalness, the resulting token strings can be conspicuous; the original AutoDAN evaluation subsequently showed that a perplexity filter sharply reduces the effectiveness of token-level attacks [Liu_2024_AutoDAN_1d6cff47]. Liao and Sun's AugmentedGCG retains candidate suffixes encountered during optimization and tests them instead of keeping only the minimum-loss suffix, increasing attack success and exposing many more successful suffixes [Liao_2024_AmpleGCG_938d71d1]. Their AmpleGCG model is trained on suffixes collected through an Overgenerate-Then-Filter (OTF) pipeline that uses model- and string-based evaluators [Liao_2024_AmpleGCG_938d71d1]. AmpleGCG-Plus later modified this pipeline by using AmpleGCG for overgeneration and Beaver-Cost for harmfulness filtering before fine-tuning the generator [Kumar_2024_LLMs_67538c80]. These developments mark a progression from single-suffix optimization to rapid generation of many query-conditioned suffixes.

#### 2. Jailbreaking Safety Alignment

Jailbreak attacks aim to circumvent safety alignment mechanisms such as reinforcement learning from human feedback (RLHF), causing a model to comply with requests it would otherwise refuse. Early jailbreaks were largely hand-crafted and circulated through online communities. Shen et al. collected 1,405 in-the-wild jailbreak prompts shared between December 2022 and December 2023, identified 131 prompt communities, and documented DAN ("Do Anything Now") as a prominent family [Shen_2024_DoAnything_0f50aa08]. Their longitudinal evidence also corrects the common assumption that such prompts invariably become obsolete quickly: 28 accounts optimized prompts for more than 100 days, and the earliest of five highly effective prompts remained online for more than 240 days [Shen_2024_DoAnything_0f50aa08]. Automatic attacks such as GCG reduced the dependence on manual prompt engineering, but introduced conspicuous suffixes and substantial optimization cost.

To address the gibberish problem, Liu et al.'s AutoDAN uses a hierarchical genetic algorithm to generate semantically meaningful jailbreak prompts and was evaluated directly against perplexity-based filtering, cross-model transfer, and cross-request generalization [Liu_2024_AutoDAN_1d6cff47]. AutoDAN-Turbo replaces a fixed search procedure with a lifelong agent that discovers, evaluates, and reuses jailbreak strategies; its experiments include successful harmful elicitation from Llama-2-13B-chat where the compared methods refused [Liu_2024_LLMs_f40cf88b]. A distinct method with the same AutoDAN name, introduced by Zhu et al., is an interpretable gradient-based attack that generates adversarial prompts left-to-right, one token at a time [Zhu_2023_AutoDAN_2563e630]. Zhan et al. later adapted this gradient-based AutoDAN as an attack against perplexity filtering in long indirect-prompt-injection contexts [Zhan_2025_LLM_ab9a7822]. Distinguishing these two AutoDAN methods is important: one is based on a hierarchical genetic algorithm, whereas the other performs gradient-guided autoregressive prompt construction.

Black-box jailbreak attacks do not require gradients or model weights. PAIR (Prompt Automatic Iterative Refinement) uses an attacker LLM to iteratively query a target LLM and refine a semantic jailbreak; the original evaluation reports that PAIR often succeeds in fewer than twenty target-model queries [Chao_2025_PAIR_590bf40a]. TAP (Tree of Attacks with Pruning) branches candidate refinements and prunes off-topic or low-scoring prompts before querying the target, exceeding 80% success on the evaluated frontier models while using fewer queries than preceding black-box methods [Mehrotra_2024_TAP_b0ffafed]. A complementary taxonomy in AdaSteer groups jailbreaks into human-designed prompts, long-tail encodings that exploit weak cross-task generalization, and prompt-optimization methods that automatically construct attack inputs [Zhao_2025_LLM_45bb4e13].

System-level interfaces provide an additional attack surface. MetaBreak directly manipulates special tokens used as chat metadata and combines four primitives to bypass internal alignment, platform-added wrappers, external content moderation, and special-token sanitization [Zhu_2025_LLM_dbd8c508]. In the authors' evaluation, MetaBreak outperformed PAP and GPTFuzzer by 11.6% and 34.8%, respectively, when content moderation was active; combining MetaBreak with those prompt-engineering attacks increased their jailbreak rates by 24.3% and 20.2% [Zhu_2025_LLM_dbd8c508].

#### 3. Indirect and Multi‑turn Prompt Injection

Direct prompt injection assumes that the attacker controls content sent directly to the model. Indirect prompt injection (IPI), by contrast, places instructions in data likely to be retrieved and processed by an LLM-integrated application [Greshake_2023_IndirectPI_428e23e8]. Greshake et al. demonstrated this remote attack model against Bing's GPT-4-powered chat, code-completion engines, and synthetic GPT-4 applications, including data theft and manipulation of API calls [Greshake_2023_IndirectPI_428e23e8].

Clinical RAG systems illustrate the importance of authority framing. MPIB contains 9,697 clinically grounded instances spanning direct and RAG-mediated injection, and evaluates both attack success and the Clinical Harm Event Rate (CHER) [Lee_2026_LLMs_674de58f]. Across twelve models, its RAG-mediated vector produced multiple-fold higher CHER than direct injection in high-risk categories, which the authors associate with retrieved clinical text being interpreted as authoritative context [Lee_2026_LLMs_674de58f].

Multi-turn conversational attacks distribute harmful intent across an interaction instead of presenting it in one prompt. The Foot-in-the-Door (FITD) attack operationalizes gradual escalation through SlipperySlopeParaphrase, which constructs intermediate requests, and ReAlign, which attempts to restore the attack trajectory after refusals [Weng_2025_LLMs_9f971db3]. Across seven evaluated LLMs, FITD achieved a 94% average attack success rate [Weng_2025_LLMs_9f971db3]. This result supports evaluating conversational trajectories, not only isolated turns.

When interactive dialogue is unavailable, ChatInject forges native chat-template role tags inside a single tool output and can encode a virtual persuasive conversation within that payload [Chang_2025_LLM_1f6233a6]. In the primary evaluation, chat-template payloads increased average attack success from 5.18% to 32.05% on AgentDojo and from 15.13% to 45.90% on InjecAgent; the multi-turn variant reached an average 52.33% success rate on InjecAgent and remained effective against prompt-based defenses [Chang_2025_LLM_1f6233a6]. This attack therefore combines role-hierarchy confusion with simulated conversational state.

#### 4. Code‑Driven Attacks

LLMs specialized for code generation present a distinct attack surface because malicious intent can be disguised inside programming tasks. A foundational security evaluation of GitHub Copilot constructed 89 security-relevant scenarios and analyzed 1,689 generated programs, approximately 40% of which were vulnerable [Pearce_2022_Copilot_3b1bf6d6]. This result concerns insecure code generation rather than jailbreak success, but it establishes that code-oriented model outputs require security evaluation distinct from ordinary natural-language refusal testing.

CodeJailbreaker, introduced in 2025, specifically targets this gap by constructing a covert channel: it embeds implicit malicious prompts inside code generation requests, thereby conveying harmful intents without articulating them directly in natural language [Ouyang_2025_LLM_4ccbdde2]. In experiments on the RMCBench benchmark, CodeJailbreaker outperformed conventional jailbreak methods that rely on explicit malicious instructions, demonstrating superior efficacy across multiple code generation tasks [Ouyang_2025_LLM_4ccbdde2]. This work highlights that adversaries can exploit code as a medium to circumvent alignment, and it underscores the urgent need to extend safety alignment to cover both natural language and code semantics, and to develop multi‑modal detection systems capable of recognizing hidden intents in programming tasks.

#### 5. Detection and Mitigation

Defending against inference‑time threats requires a combination of input‑level filtering, prompt engineering, and model‑level interventions. Common runtime defenses include instructional prevention prompts that explicitly tell the model to ignore external data, the use of delimiters to separate untrusted context from system directives, and the repetition of the original user instruction to reinforce the intended goal. However, such prompt‑based defenses are often insufficient because adversaries can craft payloads that the model treats as authoritative context.

Learned detectors and task-alignment checks offer alternatives to static keyword filters. Sentinel fine-tunes ModernBERT-large on a mixture of public and private prompt-injection data and reports 0.987 average accuracy and 0.980 F1 on an unseen internal test set [Ivry_2025_Sentinel_a518d27a]. Task Shield instead checks whether each extracted instruction and proposed tool call contributes to the user's specified goals; on AgentDojo with GPT-4o, it reduced attack success to 2.07% while retaining 69.79% task utility [Jia_2025_LLM_604891e2]. These results are measured under each paper's own evaluation setup and should not be read as guarantees against adaptive or out-of-distribution attacks. Defenses for indirect, multi-turn, and code-driven threats must also track conversational state, external-data provenance, and the cumulative intent of tool calls.

In summary, the landscape of inference‑time attacks on LLMs is defined by a progression from coarse, manually crafted jailbreak templates to automated gradient‑based suffix optimization, from direct prompt injection to stealthy indirect and multi‑turn attacks, and from plain natural‑language maneuvers to code‑infused covert channels. Detection and mitigation strategies, while advancing, remain challenged by the adaptability of attackers. Closing the gap between static defenses and adaptive threats is the central challenge for the next generation of LLM security.

Several additional dimensions merit attention. AdaSteer's multilingual evaluation instantiated low-resource-language attacks with EasyJailbreak and 100 harmful queries from AdvBench, then evaluated adaptive activation steering across LLaMA-3.1, Gemma-2, and Qwen2.5 [Zhao_2025_LLM_45bb4e13]. This is evidence about AdaSteer's experimental protocol, not a general claim that all multilingual studies use the same sample. For dataset-oriented red-teaming, the Embedded Jailbreak Template (EJT) framework disperses a harmful query across a template rather than inserting it into a fixed slot; its evaluation reported a mean attack score of 2.40 versus 2.29 for the sampled WildJailbreak-template baseline and 86.59% intent-preservation accuracy [Kim_2025_LLM_2523db75].

#### Emerging Attack Surfaces

A complementary line of research targets tool-enabled agents. Sequential Tool Attack Chaining (STAC) composes individually benign-looking tool calls into a harmful multi-turn sequence whose effect becomes apparent only at execution [Li_2025_LLM_c2206a72]. The primary evaluation generated 483 STAC cases comprising 1,352 user-agent-environment interaction sets across ten failure modes; attack success exceeded 90% in most evaluated settings, while the proposed reasoning-driven defense prompt reduced success by up to 28.8% [Li_2025_LLM_c2206a72]. This threat is difficult for single-turn classifiers because malicious intent is distributed across state changes and tool invocations.

Dedicated primary benchmarks now characterize IPI in tool-enabled agents. InjecAgent contains 1,054 test cases spanning 17 user tools and 62 attacker tools [Zhan_2024_InjecAgent_49e6e6a4]. AgentDojo is an extensible environment with 97 realistic user tasks and 629 security test cases, designed to evaluate utility and security under evolving attacks and defenses [Debenedetti_2024_AgentDojo_349884ff]. Benchmark scores can still overstate robustness when attacks are non-adaptive: Zhan et al. evaluated eight IPI defenses and bypassed every one with defense-specific adaptive attacks, consistently exceeding 50% attack success [Zhan_2025_LLM_ab9a7822].

In tool-based environments, attackers can embed deceptive instructions in tool documentation to manipulate an agent's tool selection and induce harmful tool calls [Shi_2025_LLM_f0833c22]. PoisonedRAG targets a different external component: it injects optimized malicious texts into a RAG knowledge database [Zou_2025_PoisonedRAG_f4ff19ff]. With five injected texts per target question in databases containing millions of documents, the primary study reported attack success above 90% across NQ, HotpotQA, and MS-MARCO, including 97% on NQ in the black-box setting [Zou_2025_PoisonedRAG_f4ff19ff].

#### Code Decomposition and Generative Suffixes

Code-oriented attacks also exploit multi-turn structure. Wahed et al. (2025) introduced a Code Decomposition Attack in which an LLM-guided meta-prompt reframes a complex malicious request into up to five subtasks and augments each subtask with jailbreaking strategies; each conversational turn is annotated with a maliciousness label that reflects the cumulative risk of the sequence [Wahed_2025_Mocha_c0ec2d2c]. This design highlights that detection systems must track evolving malicious intent across turns instead of judging each prompt independently [Wahed_2025_Mocha_c0ec2d2c].

On the optimization front, AdvPrompter alternates between optimizing readable adversarial suffix targets and fine-tuning a generator on those targets; once trained, the generator produces query-conditioned suffixes through ordinary next-token prediction [Paulus_2025_AdvPrompter_d888b27b]. GCG's original multi-prompt, multi-model formulation instead optimizes a single suffix by aggregating losses and gradients across behaviors and models [Zou_2023_Universal_ab8745c2]. Many-shot Jailbreaking exploits long context windows by supplying hundreds of demonstrations of undesirable behavior, with attack effectiveness following a power law over the number of demonstrations in the evaluated regimes [Anil_2024_ManyShot_08d20dea]. Together, these attacks operate across distinct axes: learned suffix generation, universal optimization, and long-context in-context learning.

#### Detection and Adaptive Defenses

Defenders have explored both input filtering and model-level signals. Intermediate-layer hidden states and gradients provide discriminative features for instruction detection, and Wen et al. use them in a detector evaluated against indirect prompt injection [Wen_2025_Defending_cadb901b]. UniGuardian takes a different approach: it groups prompt injection, backdoor, and adversarial inputs as Prompt Trigger Attacks and performs unified detection and text generation in a single forward pass [Lin_2025_Uniguardian_552288e3]. No single static filter should be assumed to cover direct injection, external-data poisoning, multi-turn state manipulation, and adversarial suffixes.

The direct/indirect distinction is operational: direct injection gives the attacker control over content submitted to the model, whereas indirect injection places instructions in external data expected to be retrieved by an application [Greshake_2023_IndirectPI_428e23e8]. VortexPIA demonstrates a concrete black-box IPI objective beyond one-turn task redirection: it injects false-memory content that causes conversational applications to request attacker-selected categories of private information from users in batches [Cui_2025_LLMs_095e8484]. Its evaluation covers six LLMs, four datasets, and several open-source LLM-integrated applications [Cui_2025_LLMs_095e8484].

Collectively, these developments reveal an expanding attack surface defined by multilingual encoding, long-context manipulation, adaptive IPI, and tool-level orchestration. Defensive progress requires continuous red-teaming and benchmarks that capture multi-turn tool interactions, task utility, environment state, and defense-aware adaptive adversaries.


## Hallucinations as a Security and Integrity Threat

#### From Factual Inconsistency Detection to Security Risk

The generation of factually incorrect or unsupported content by large language models (LLMs) was long treated primarily as an accuracy problem, with evaluation focused on surface-level overlap metrics such as ROUGE or BERTScore. A decisive shift occurred in 2024, when the community began to view factual inconsistencies—particularly those that appear plausible and confident—as a serious security vulnerability capable of enabling misinformation, data leakage, and unsafe automated decision-making. This reconceptualization placed a premium on fine-grained, claim-level verification that could reliably identify statements not grounded in provided evidence or reliable knowledge. Hallucinations in natural language generation are often subtle and difficult to detect, requiring more than superficial checks [Anaokar_2025_Halludetect_9248653c]. The presence of hallucinations poses a serious challenge in real‑world applications, including legal assistance and customer support, where erroneous outputs can lead to misleading advice or operational failures [Anaokar_2025_Halludetect_9248653c]. The community thus reframed efficient and precise verification as a prerequisite for trustworthy deployment: a single hallucination can propagate misinformation with the same apparent authority as a truthful statement, undermining both user trust and system integrity.

This new security perspective was reinforced by the observation that hallucinations extend beyond factual misstatements. Faithfulness hallucinations include not only rephrased surface-level facts but also cognitive statements—claims that require inference from the given context and that are harder to evaluate than simple recollection of source material [Tang_2025_Cognibench_0b308648]. A model that invents a plausible but unsupported conclusion about a medical condition, a legal precedent, or a financial regulation can cause harm even if every atomic fact it cites is correct. The CogniBench benchmark, inspired by legal evidence assessment, was designed to capture such nuanced unfaithfulness, and its large-scale variant CogniBench‑L enables training detectors for both factual and cognitive hallucinations [Tang_2025_Cognibench_0b308648]. These developments highlight that security‑critical domains cannot rely on surface accuracy alone; comprehensive integrity protection demands detection of all forms of unsupported inference.

While early hallucination detection research focused on sentence-level classification, more recent work emphasizes span-level detection, which enables precise identification of unsupported content [Elchafei_2025_LLM_94763a97]. In 2024, Gu et al. introduced ANAH, a bilingual dataset for analytical hallucination annotation and span-level detection [Gu_2024_Anah_c586886a]. The same year, Ravi et al. released LYNX, the first open-source LLM specialized in reference-free hallucination detection for retrieval-augmented generation (RAG) settings. LYNX surpassed both GPT‑4o and Claude‑3‑Sonnet on HaluBench, a comprehensive 15k‑sample benchmark spanning real‑world domains such as finance and medicine [Ravi_2024_Lynx_ce273f20]. Both ANAH and LYNX operate by treating hallucination detection as an NLI task: they assess whether a claim is entailed by, contradictory to, or neutral with respect to provided context, and flag unsupported statements with high precision. By deploying such detectors as input or output filters, systems can prevent unverified content from reaching users or downstream modules, thereby mitigating the risk of misinformation dissemination.

Despite these advances, the security implications of hallucination are not limited to the propagation of false factual assertions. Plausible but fabricated code snippets, configuration instructions, or API calls generated by LLMs represent an emerging threat vector. Such outputs could introduce exploitable vulnerabilities, trigger unintended system actions, or cause data leakage if executed or adopted by automated pipelines. However, the corpus of sources reviewed for this survey does not include dedicated studies that systematically quantify the security impact of code‑level hallucinations or propose countermeasures specific to that modality. The absence of such work points to a significant gap in the literature. Nevertheless, the established difficulty of detecting subtle, coherent falsehoods in natural language—the very characteristics that ANAH, LYNX, and the fine‑grained claim‑checking methods are designed to unmask—suggests that analogous trustworthiness challenges will equally apply to code generation, where errors are often syntactically valid and therefore appear authoritative.

#### Benchmarks and Evaluation Frameworks

The shift toward security-motivated hallucination assessment stimulated richer benchmarks. HaluEval introduced a large collection of generated and human-annotated hallucination samples for response and detection evaluation [Li_2023_HaluEval]. HaluBench subsequently assembled 15,000 context-question-answer examples, including finance and medicine, with PASS/FAIL faithfulness labels and deliberately difficult, plausible hallucinations [Ravi_2024_Lynx_ce273f20].

CogniBench, introduced in 2025, tackles a specific blind spot of previous resources: it evaluates faithfulness hallucinations that are not simple rephrasings of source material but rather cognitive statements requiring inference [Tang_2025_Cognibench_0b308648]. By constructing a rigorous assessment framework inspired by legal evidence evaluation, CogniBench enables the measurement of faithfulness at multiple levels and provides a scalable annotation pipeline for keeping pace with rapidly evolving LLMs. The large-scale CogniBench‑L variant further facilitates training accurate detectors for both factual and cognitive hallucinations.

Multi‑dimensional faithfulness evaluation has also been advanced through benchmarks that stress‑test models under adversarial or ambiguous conditions. One prominent example, FaithEval (Ming et al., 2024), tests contextual faithfulness across unanswerable, inconsistent, and counterfactual contexts. Although FaithEval is not part of the citable source set for this survey, its design illustrates the community's movement toward deliberately challenging models with incomplete, contradictory, or fabricated contexts in order to expose subtle unfaithfulness. Combined with HaluBench's domain‑diverse coverage, such frameworks provide a more complete picture of integrity risks.

A notable limitation of current benchmarks is their restricted linguistic coverage. Almost all hallucination detection datasets focus on English, and multilingual benchmarks remain sparse, primarily tied to reference‑based tasks such as machine translation and summarization, which poorly represent real‑world LLM usage [Islam_2025_LLM_e0a71a22]. This scarcity is itself a security concern, because non‑English misinformation and code‑generation hallucinations can propagate in linguistic environments where detection tools are least mature.

#### Internal Representations for Hallucination Detection

A major inflection point beginning in mid‑2024 was the move away from purely external verification toward white‑box hallucination detection that exploits the LLM’s own internal representations. Instead of treating the model as a black box and checking outputs against retrieved knowledge, researchers began to analyze hidden states, attention patterns, and token‑level probabilities to infer whether a generated statement is likely to be truthful. This approach is attractive for security‑sensitive applications because it operates in a single forward pass, adds minimal latency, and does not depend on external knowledge bases that may be outdated or incomplete [Tong_2025_LLM_559891bc]. Studies have shown that LLMs exhibit distinct hidden-state patterns when producing truthful versus fabricated answers. Li et al. use Fourier analysis to extract frequency-domain features that distinguish faithful from hallucinated content [Li_2025_LLM_ff8c4a51]. TruthX instead learns a truthful latent space and edits hidden states to reduce hallucinations [Zhang_2024_TruthX].

Uncertainty‑based detection has been a particularly fruitful instantiation of internal‑representation methods. HaluNet, introduced by Tong et al. in 2025, exemplifies the integration of complementary uncertainty sources: it combines semantic embeddings from model hidden layers with token‑level probabilistic confidence and distributional uncertainty in a multi‑branch architecture that performs one‑pass hallucination detection [Tong_2025_LLM_559891bc]. By capturing both epistemic uncertainty (knowledge gaps) and aleatoric uncertainty (contextual ambiguity) from internal signals, HaluNet reduces the risk of acting on confident‑sounding falsehoods, directly addressing the security imperative of preventing unsafe automated decisions. Experiments on SQuAD, TriviaQA, and Natural Questions showed that HaluNet delivers strong detection performance and favorable computational efficiency, with or without access to context [Tong_2025_LLM_559891bc].

Attention‑based signals provide another complementary channel for white‑box detection. Shelmanov et al. analyzed attention patterns in the current generated token and found that while most attention heads show negligible correlation with hallucination, a subset of heads exhibits moderate positive or negative associations, particularly with the immediately preceding token [Shelmanov_2025_LLM_7172d579]. Based on these observations, they introduced an uncertainty head (UHead) that achieves substantial gains: in in‑domain evaluation, UHead outperformed the best unsupervised method by 16 percentage points in PR‑AUC, and in out‑of‑domain settings the improvements reached up to 23 points [Shelmanov_2025_LLM_7172d579]. This work demonstrates that fine‑grained attention analysis can efficiently flag hallucinations without requiring additional sampling or external retrieval.

Consistency‑based approaches further extend white‑box detection by leveraging variability across multiple sampled responses. HalluCounter, a reference‑free detection pipeline, computes entailment, neutrality, and contradiction scores between query‑response and response‑response pairs, then feeds aggregated NLI features into a hallucination classifier that also identifies the least hallucinated answer among the candidates [Urlana_2025_LLM_d7c09bcb]. In a related direction, Hou et al. proposed a method that generates logically‑related statements organized in a tree structure and performs consistency checks among them to detect non‑factual statements [Hou_2024_LLM_1df5a9a5]. While these approaches require multiple generations and are therefore more costly, they illustrate how internal variability can serve as a proxy for uncertainty when full access to weights is available. The broader trend is clear: by mid‑2024, the community had begun to accept that the information required to detect many hallucinations already exists within the model’s own computations, and that architectural innovations in probing, spectral analysis, attention‑head exploitation, and multi‑granular uncertainty fusion can transform raw internal signals into practical security safeguards.

A significant limitation of these white‑box methods is their requirement for full access to model weights and activations, which is incompatible with API‑only black‑box models. However, for applications that control the inference stack—such as enterprise‑grade RAG systems, medical QA assistants, or code‑generation copilots deployed on‑premises—internal representation detectors offer a powerful layer of integrity assurance. They can intercept hallucinated claims before they reach the user, flag suspicious outputs for review, or trigger fallback mechanisms that ground responses in verified information. The combination of efficient internal detectors with the external fact‑checking pipelines described earlier represents the current frontier of security‑oriented hallucination mitigation, and the surveyed literature indicates that integrating both modalities will be essential to counteract the increasingly subtle and context‑aware hallucinations that LLMs produce.

Emerging evidence indicates that more advanced reasoning models are generating hallucinations at increasingly concerning rates, and real-world cases of fabricated outputs are already prompting legal accountability. In safety-critical domains such as medicine and infrastructure engineering, a single plausible but unsupported claim can propagate misinformation and erode user trust [Moslonka_2025_LLMs_76b3b56e]. As LLM-agent-enabled systems proliferate, the compounding cost of undetected hallucinations makes integrity-aware detection an indispensable safeguard for autonomous deployment.


## Cross-Cutting Defenses and Mitigation Strategies

The defense of large language models (LLMs) has evolved beyond isolated countermeasures for individual threat categories toward cross‑cutting strategies that compose alignment hardening, pre‑ and post‑generation filtering, input/output sanitization, adversarial training, and proactive red teaming into resilient multi‑layered systems. A defense‑in‑depth philosophy motivates the introduction of additional independent defense layers that evaluate the unsafety level of produced outputs and perform post‑generation filtering, which can serve as an ultimate defense against alignment failures [Arazzi_2026_Securebreak_0e3adcf7]. Complementarily, alignment methods based on Reinforcement Learning from Human Feedback (RLHF) and Direct Preference Optimization (DPO), together with system-level guardrails that monitor prompts and generated text, form foundational layers of a comprehensive defense stack.

#### Defense‑in‑Depth and Multi‑Layered Strategies

Defense‑in‑depth leverages multiple independent safeguards so that the failure of one layer can be compensated by another. On the input side, perplexity-based filtering examines prompts for anomalous statistics and discards those that appear adversarial. At the data level, spectral signatures detect poisoned training samples through anomalous internal representations [Tran_2018_SpectralSignatures]; however, their effectiveness is sensitive to configuration choices, and widely used settings are often suboptimal [Le_2025_Signature_fc7a3218]. Together, these layers reduce the overall attack surface, but even stacked static defenses can be circumvented by adaptive adversaries, a theme revisited later.

#### Alignment Hardening and Safety Training

Alignment‑based hardening constitutes the inner loop of LLM defense. Supervised fine-tuning on curated safety data provides a useful but incomplete alignment layer. RLHF and DPO further optimize responses from preference data. Liu et al. (2025) applied DPO to safety‑oriented preference data from Anthropic‑HH and other safety corpora, training models to prefer harmless over harmful responses [Liu_2025_LLM_27335912]. Beyond reward-based alignment, instruction hierarchy trains models to prioritize trusted instructions over lower-privilege content [Wallace_2024_InstructionHierarchy]. This training‑time hardening embeds a persistent priority structure that cannot be easily overridden by injected lower‑priority prompts.

#### Guardrails, Filtering, and Input/Output Sanitization

System-level guardrails act as intermediaries that inspect both incoming prompts and model outputs, preventing obviously malicious content from reaching the model or the end user. For indirect prompt injection, sanitization methods like PISanitizer locate and remove injected tokens by analyzing attention weights across consecutive tokens; they reduce the attack success rate to nearly zero while preserving target task utility [Geng_2025_LLMs_16cfd21e]. System prompt extraction is countered by appending safety instructions (instruction defense), wrapping the system prompt with double‑layered safety instructions (sandwich defense), and applying output filtering that blocks responses containing the original system prompt [Das_2025_System_cda316c4]. At the output level, post‑generation filtering that uses an external Judge LLM to intercept and block harmful outputs provides an additional defense layer beyond intrinsic alignment [Arazzi_2026_Securebreak_0e3adcf7]. Nevertheless, a wide array of jailbreaking techniques can bypass these filters, underscoring the need for more fundamental hardening strategies.

#### Constrained Decoding for Hallucination Prevention

Decoding‑time interventions offer a complementary line of defense against factual inaccuracies without retraining. Yang et al. (2025) introduced InEx, a cross‑modal verification framework that calibrates logits and applies uncertainty penalties during generation to reduce hallucinations [Yang_2025_Inex_187a262a]. The absence of certified constrained decoding for hallucination prevention in the retrieved literature highlights an open frontier where robustness against fabricated content must be mathematically grounded.

#### Adversarial Training and Training‑Time Hardening

Adversarial training in the LLM domain often takes the form of fine‑tuning on explicitly crafted attack prompts to teach secure behavior. Instruction-hierarchy training is a representative example: by exposing the model to conflicting lower-privilege content while enforcing a strict priority policy, the resulting model learns to disregard injected instructions [Wallace_2024_InstructionHierarchy]. More generally, prevention-based defenses can be implemented at training time, as shown by Jatmo, which fine-tunes a base LLM on a single task without supplying task instructions, thereby removing the instruction-following behavior exploited by prompt injection [Piet_2023_Jatmo]. These training‑time approaches embed security directly into model weights, making them harder to bypass than prompt‑level measures.

#### Red Teaming as a Defensive Feedback Loop

Red teaming has evolved from a manual auditing practice into an integral component of the defense lifecycle. Human red teaming uncovers nuanced weaknesses, while automated red teaming uses adversarial attacks and benchmarks to probe defenses at scale.

#### Prompt‑Level Hardening versus Architectural Defenses

A fundamental distinction in the defense landscape lies between surface‑level prompt fortification and deeper weight‑level interventions. Prompt‑based defenses construct special instructions—such as in‑context exemplars or explicit delimiters—without modifying model weights. These methods are lightweight and rapidly deployable, but they operate purely at the textual surface and can be overridden by adversarial prompts that subvert the protective instructions. In contrast, architectural and training‑time defenses embed security more deeply. Instruction hierarchy trains the model to enforce a strict priority ordering so that lower-priority injected instructions are systematically disregarded [Wallace_2024_InstructionHierarchy]. This complementary relationship—prompt hardening as a rapidly configurable outer shell and architectural fine‑tuning as a persistent inner foundation—exemplifies the defense‑in‑depth philosophy.

#### Safety–Utility Trade‑offs

The tension between safety enforcement and the model’s ability to fulfill legitimate requests remains a central challenge. Some defenses explicitly aim to preserve utility: PISanitizer, for instance, reduces attack success rate to nearly zero while maintaining target task performance [Geng_2025_LLMs_16cfd21e]. However, over‑refusal—where benign inputs are incorrectly blocked or refused—is a widely recognized side effect of aggressive alignment and filtering; the retrieved literature does not include dedicated studies that quantify over‑refusal rates with the same rigor applied to attack success. Achieving a robust safety–utility balance requires careful calibration of protective mechanisms, and the ability to tune safety parameters without expensive retraining remains a valuable design goal.

#### Limitations Against Adaptive Multi‑Vector Attacks

Despite the layered defenses described above, current state‑of‑the‑art methods remain brittle when faced with adaptive adversaries that combine multiple attack vectors. LLMs remain susceptible to jailbreaking techniques that circumvent safety filters. The absence of structural constraints on agent behavior allows attackers to trigger malicious tool invocations even when the model is guarded by advanced prompting or detection models [Miculicich_2025_LLM_fdef6034]. These observations indicate that current heuristics are insufficient against persistent, multi‑turn, multi‑vector attack strategies and motivate the need for provably robust frameworks.

#### Certified Robustness and Emerging Directions

In the poisoning domain, formal guarantees remain scarce. Lorenz et al. (2024) introduced FullCert, a framework that provides deterministic end‑to‑end certificates against both training‑time poisoning and inference‑time evasion attacks by unrolling the entire training and inference procedure into a single computational graph and applying sound interval bounds [Lorenz_2024_Fullcert_7dbc4820]. They noted, however, that certifying the robustness of training is far more challenging than inference due to the attacker’s higher degree of freedom over multiple data points and the much deeper computational graph that spans forward and backward passes over an entire dataset; thus, existing approaches provide only probabilistic guarantees while severely limiting attacker influence to a few samples or pixels [Lorenz_2024_Fullcert_7dbc4820]. Beyond FullCert, no deterministic certified defenses against arbitrary poisoning have been reported. For jailbreaks and hallucination prevention via constrained decoding, the retrieved literature does not contain certified frameworks, signaling open research frontiers where mathematical verification of safety properties is urgently needed. As attackers continue to develop adaptive, multi‑vector strategies, the journey toward robust and generalizable LLM defenses will require not only richer combinations of existing methods but also mathematically grounded frameworks that can provide provable safety guarantees.

Two additional directions reinforce the cross-cutting nature of defense. Sheshadri et al. (2024) observed that adversarial training can fail to fix specific vulnerabilities that were not adversarially trained on, and demonstrated that targeted latent adversarial training—which perturbs latent activations rather than input tokens—improved robustness to unseen jailbreak and backdoor attacks, outperformed a strong baseline with orders of magnitude less compute, and enabled unlearning that resists re-learning [Sheshadri_2024_LLMs_ecd68cc1]. Complementing this, Kumar et al. (2024) introduced AmpleGCG-Plus as an efficient red-teaming tool, showing that model initialization, data quantity, and data quality improve the learning of gibberish adversarial prompts and exposing persistent vulnerabilities in current safety mechanisms [Kumar_2024_LLMs_67538c80]. On the guardrail side, Liu et al. (2025) introduced Aegis, which co-evolves attacks and defenses to adapt beyond static, manually designed templates [Liu_2025_Aegis_6081be1b]; Yao et al. (2025) similarly motivated adaptive AI firewall designs for multirole system flows [Yao_2025_LLM_a1c8adc0]. The retrieved corpus does not document low-rank adaptation regularization as a defense; the closest training-time mechanism is latent adversarial training on hidden activations.


## Testing Methodologies and Evaluation

Systematic evaluation of large language model (LLM) security relies on carefully curated benchmarks, standardised quantitative metrics, and reproducible evaluation pipelines. This section reviews the empirical apparatus employed across four principal threat categories: prompt injection and agent manipulation, jailbreak attacks, malicious code generation, and hallucination detection with faithfulness verification. Table 1 provides a consolidated overview of the major testing frameworks, metrics, and representative studies. While the survey targets a comprehensive scope, several notable benchmarks – including CWE‑BENCH‑PYTHON for code security, FaithEval for multi‑dimensional faithfulness, and AdvBench for adversarial suffix attacks – are not covered by the retrieved corpus; accordingly, the discussion below is circumscribed to the categories for which direct evaluation evidence is present in the available material.

#### Prompt Injection and Agent Security Evaluation

Prompt injection attacks, especially indirect variants that exploit retrieved or tool‑returned content, constitute a rapidly maturing threat. Several benchmarks have been proposed to evaluate the security of LLM‑powered agents and retrieval‑augmented systems. Widely used suites include AgentDojo, Agent Security Bench, and InjecAgent, which simulate tool‑calling and RAG scenarios. Bhagwatkar et al. (2025) identified critical limitations in these benchmarks: many do not model real‑world situations appropriately and sometimes use skewed metrics that make weak defenses appear deceptively effective [Bhagwatkar_2025_Indirect_2ccd3225]. To remedy this, the authors proposed targeted fixes and constructed a much stronger three‑stage cascaded attack strategy that escalates from existing formatted injections to second‑order semantic deception templates and finally to a defense‑aware adaptive LLM mutator [Bhagwatkar_2025_Indirect_2ccd3225]. The authors also released corrected benchmark versions and evaluated a Sanitizer defense, which—not the attack protocol—achieved the reported security-utility trade-off across AgentDojo, Agent Security Bench, InjecAgent, and τ-bench [Bhagwatkar_2025_Indirect_2ccd3225].

In parallel, Lee et al. (2026) introduced MPIB, a dataset‑and‑benchmark suite for evaluating clinical safety under prompt injection in LLM and RAG systems [Lee_2026_LLMs_674de58f]. MPIB covers both direct user‑channel injection (V1) and RAG‑mediated indirect injection (V2) across clinically grounded scenarios, and reports outcomes using a harm taxonomy together with the Attack Success Rate (ASR) and a novel Clinical Harm Event Rate (CHER) [Lee_2026_LLMs_674de58f]. The benchmark contains 9,697 curated instances produced via multi‑stage quality gates and clinically informed linting; across a diverse model matrix and five defense configurations, ASR and CHER can diverge, and defense effectiveness depends on whether adversarial instructions appear in the query or in retrieved context [Lee_2026_LLMs_674de58f]. MPIB is accompanied by a reproducible evaluation harness and a redacted release policy for high‑risk payloads.

Expanding the scope to multi‑agent systems, Triedman et al. (2025) systematically investigated how compromised metadata and “confused deputy” vulnerabilities can hijack control flows in multi‑agent architectures, even when individual agents refuse unsafe actions [Triedman_2025_Multi_99df1b61]. Their work extends indirect prompt injection (IPI) evaluation beyond single‑agent setups, highlighting the need for benchmarks that capture complex agent interactions and tool‑augmented workflows.

#### Jailbreak Evaluation Metrics

Beyond prompt injection, jailbreak attacks that attempt to elicit forbidden outputs from aligned LLMs have been measured through standardised metrics. Liu et al. (2024) employed two evaluation metrics drawn from existing open‑source jailbreak benchmarks: the Harmbench Attack Success Rate (ASR), computed by a carefully fine‑tuned Llama‑2‑13B classifier that judges whether a response is both relevant and harmful, and the StrongREJECT Score, an auto‑grading system that captures nuanced distinctions in response quality and aligns closely with human evaluators [Liu_2024_LLMs_f40cf88b]. For iterative attack methods such as AutoDAN‑Turbo, the evaluation is supplemented with Total Strategies Found (TSF) and Average Jailbreak Rounds (AJR), providing insight into both attack diversity and efficiency [Liu_2024_LLMs_f40cf88b]. These metrics have become a reference for jailbreak studies, offering a reproducible quantification of attack effectiveness.

#### Malicious Code Generation Benchmarks

A critical threat to LLM security is the generation of malicious code. The first benchmark specifically designed to assess this capability is RMCBench, introduced by Chen et al. in 2024 [Chen_2024_Rmcbench_19963c81]. RMCBench comprises 473 prompts split into two scenarios: a *text‑to‑code* scenario where natural‑language descriptions request code generation, and a *code‑to‑code* scenario requiring translation or completion of existing malicious code [Chen_2024_Rmcbench_19963c81]. The dataset covers 11 categories of malware (e.g., viruses, worms) written in 9 programming languages such as Python, Java, and C++ [Chen_2024_Rmcbench_19963c81]. RMCBench was built from malicious code collected from 392 GitHub repositories; ChatGPT-3.5 generated natural-language descriptions, which the authors used to manually construct the benchmark prompts [Chen_2024_Rmcbench_19963c81].

The standard evaluation protocol on RMCBench employs GPT‑4 as an automatic judge to label each model response as GOOD (refusal to generate), BAD (malicious output), or UNCLEAR, and reports the **Refusal Rate** – the percentage of prompts eliciting a GOOD response [Chen_2024_Rmcbench_19963c81]. Chen et al.‘s original study on 11 representative LLMs revealed an average refusal rate of only 28.71%, with a stark difference between the text‑to‑code (40.36%) and code‑to‑code (11.52%) scenarios [Chen_2024_Rmcbench_19963c81]. This indicates that LLMs are far more vulnerable when completing or translating already‑malicious code than when prompted with explicit descriptions.

Building on this, Ouyang et al. (2025) refined the evaluation metrics by introducing **Attack Success Rate (ASR)** – the proportion of malicious requests that are *not* rejected – and **Malicious Ratio (MR)** – the fraction of generated code that faithfully realises the malicious intent [Ouyang_2025_LLM_4ccbdde2]. Using the same RMCBench benchmark, their CodeJailbreaker attack achieved an average ASR of nearly 80% and an MR close to 65% across seven commonly used LLMs (five general and two code‑specialised), marking an improvement of over 50% compared to prior jailbreak techniques [Ouyang_2025_LLM_4ccbdde2]. CodeJailbreaker operates by embedding malicious intents implicitly in commit messages, a covert channel that bypasses safety mechanisms trained on explicit instructions [Ouyang_2025_LLM_4ccbdde2]. In the block‑level completion task, even the baseline EMP method attained an average ASR of 96.20% and MR of 74.77%, demonstrating that current LLMs lack robust defenses against fine‑grained code completion attacks; CodeJailbreaker further raised these to 98.21% ASR and 79.24% MR [Ouyang_2025_LLM_4ccbdde2]. These results underscore the inadequacy of static benchmarks for capturing worst‑case security because new attack methods can drastically inflate success rates.

#### Hallucination Detection Benchmarks

Hallucination – the generation of unfaithful or unsupported information – is assessed through a growing array of evaluation suites. Early works included SelfCheckGPT, a sampling-based black-box detector [Manakul_2023_SelfCheckGPT], and HaluEval, a benchmark of generated and human-annotated hallucination samples [Li_2023_HaluEval]. While useful, these datasets were largely synthetic and lacked domain diversity [Ravi_2024_Lynx_ce273f20]. In 2024, Ravi et al. introduced **HaluBench**, a benchmark of 15,000 samples that, for the first time, incorporated real‑world domains – specifically finance and medicine – making it the first open‑source hallucination benchmark spanning specialised industrial tasks [Ravi_2024_Lynx_ce273f20]. HaluBench combines DROP, HaluEval, RAGTruth, FinanceBench, PubMedQA, and COVIDQA; each instance contains context, a question, an answer, and a PASS/FAIL faithfulness label [Ravi_2024_Lynx_ce273f20]. The benchmark deliberately includes hard‑to‑detect hallucinations – answers that appear plausible but contradict the provided context [Ravi_2024_Lynx_ce273f20]. On this dataset, the LYNX model, a fine‑tuned Llama‑3‑70B‑Instruct variant, achieved reference‑free hallucination detection superior to GPT‑4o, Claude‑3‑Sonnet, and other closed‑source alternatives [Ravi_2024_Lynx_ce273f20]. Mala et al. (2025) later used HaluBench – with 13,867 samples – to study hybrid mitigation strategies, confirming its utility for comparing detection approaches [Mala_2025_Hybrid_48468dfd].

Beyond single‑turn binary classification, Anaokar et al. (2025) proposed HalluDetect, a structured multi‑stage LLM‑based evaluation framework designed to detect, score, and explain hallucinations in multi‑turn chatbot conversations [Anaokar_2025_Halludetect_9248653c]. HalluDetect was evaluated on the DetectorEval dataset using human annotation; annotators labelled detected hallucinations as Correct or Wrong and reported missed instances, yielding per‑conversation precision and recall metrics that offer a finer‑grained assessment than simple accuracy [Anaokar_2025_Halludetect_9248653c].

The scope of hallucination evaluation has further broadened to multimodal domains. Liu et al. (2025) evaluated hallucination mitigation on five vision‑language benchmarks – HallusionBench, Object‑HalBench, MMHal‑Bench, AMBER, and MMStar – using question‑level accuracy, figure‑level accuracy, overall accuracy, and hallucination rates [Liu_2025_Mitigating_b63ac3f0].

#### Faithfulness and Citation Evaluation

Ensuring that generated statements are supported by retrieved documents is critical for retrieval‑augmented generation (RAG). Beyond binary hallucination detection, recent work has targeted multi‑level faithfulness and citation verification. Tang et al. (2025) proposed **CogniBench**, a benchmark specifically designed to evaluate faithfulness hallucinations involving “cognitive statements” – claims that require inference from the context rather than mere factual restatement [Tang_2025_Cognibench_0b308648]. They further introduced an automatic annotation pipeline to scale the dataset (CogniBench‑L) and train detectors capable of handling both factual and cognitive hallucinations [Tang_2025_Cognibench_0b308648].

Parallel efforts have focused on the evaluation of citation support. Zhang et al. (2024a, 2024b) examined the use of faithfulness metrics to automatically judge whether a citation fully, partially, or not at all supports a generated statement [Zhang_2024_Comparative_d35d7fec, Zhang_2024_Fine_79ed226e]. Their comparative framework assessed metric performance through correlation with human judgments, classification evaluation, and retrieval evaluation, revealing that no single metric consistently excels across all three support levels [Zhang_2024_Comparative_d35d7fec]. This finding highlights the need for more nuanced, multi‑dimensional evaluation schemes that move beyond simple binary pass/fail decisions.

#### Red‑Teaming Frameworks and Automated Evaluation Suites

The surveyed literature illustrates a transition from ad‑hoc testing to systematic, automated red‑teaming. The cascaded attack strategy of Bhagwatkar et al. (2025) serves as a reusable adversarial probe that can be deployed across multiple agent benchmarks, functioning as a standardised strength evaluator [Bhagwatkar_2025_Indirect_2ccd3225]. MPIB provides a fully packaged evaluation harness with fixed splits, a clinical‑harm taxonomy, and dual metrics (ASR + CHER), enabling reproducible comparisons across models and defense configurations [Lee_2026_LLMs_674de58f]. For code generation, the CodeJailbreaker pipeline integrates with RMCBench to deliver a structured attack and evaluation workflow [Ouyang_2025_LLM_4ccbdde2]. In the jailbreak domain, AutoDAN‑Turbo’s reporting of TSF and AJR alongside Harmbench ASR and StrongREJECT forms a comprehensive evaluation suite [Liu_2024_LLMs_f40cf88b]. Together, these components move the community toward reproducible, multi‑faceted red‑teaming, although a unified, cross‑category framework remains absent.

#### Temporal Evolution and Cross‑Category Observations

The benchmarks and metrics described above reveal a clear evolutionary trajectory. Early evaluation concentrated on single‑turn safety violations: Harmbench ASR and StrongREJECT (2024) quantified basic jailbreak success, while HaluEval provided synthetic hallucination samples. By 2024–2025, community effort shifted toward realistic, domain‑rich settings – HaluBench encompassed healthcare and finance [Ravi_2024_Lynx_ce273f20], and RMCBench formalised malicious code generation. The period 2025–2026 saw the emergence of multi‑turn, tool‑augmented, and multi‑agent evaluation: AgentDojo, Agent Security Bench, and InjecAgent incorporated tool‑calling agents, MPIB introduced clinically grounded indirect injection, and Triedman et al. explored compromised metadata in multi‑agent systems [Bhagwatkar_2025_Indirect_2ccd3225, Triedman_2025_Multi_99df1b61]. Adaptive attack resistance was explicitly addressed by the cascaded approach of Bhagwatkar et al., which demonstrated that strong attacks can surface vulnerabilities missed by static benchmarks [Bhagwatkar_2025_Indirect_2ccd3225]. Multimodal evaluation was added in 2025 with benchmarks like HallusionBench and MMHal‑Bench. Hallucination evaluation similarly matured from binary single‑turn labelling to multi‑turn precision‑recall assessment with HalluDetect [Anaokar_2025_Halludetect_9248653c].

A cross‑category comparison reveals that metrics are tightly coupled to threat semantics. Prompt injection and jailbreak attacks use ASR to measure the model’s ability to gate harmful outputs, with extensions such as CHER for clinical harm and StrongREJECT for response quality. Malicious code generation adds the Malicious Ratio to assess not only whether the model capitulates but also the fidelity of the generated payload. Hallucination detection relies on classifier‑style measures – accuracy, precision, recall – that compare outputs against ground‑truth faithfulness. This heterogeneity makes direct comparison of security postures across threat vectors difficult and underscores the lack of a unified benchmark that spans all categories under a common evaluation protocol.

#### Limitations of Current Testing Approaches

Several limitations persist in the current testing methodologies. **Dataset biases** are evident: RMCBench is derived from GitHub repositories and a fixed set of malware categories, potentially missing novel attack patterns [Chen_2024_Rmcbench_19963c81]. HaluBench, though diverse, is drawn from specific English‑centric QA collections and does not capture the full linguistic variety of deployment settings. **Static benchmarks** fail to capture adaptive attack resistance. Bhagwatkar et al. (2025) showed that introducing a defense‑aware adaptive attacker dramatically reduces the apparent safety of tested agents, exposing weaknesses that original static tests miss. Similarly, the block‑level completion results of Ouyang et al. (2025), where even a baseline attacker achieved over 96 % ASR, illustrate that current code‑generation safeguards are brittle [Ouyang_2025_LLM_4ccbdde2]. **Absence of a unified threat benchmark** means models are typically evaluated on isolated threats; composite attacks that simultaneously exploit prompt injection, jailbreak, and hallucination generation remain unassessed. Finally, evaluation of indirect prompt injection in complex web‑based and multi‑agent environments is still nascent, with MPIB and the multi‑agent study of Triedman et al. (2025) representing pioneering but limited explorations [Lee_2026_LLMs_674de58f, Triedman_2025_Multi_99df1b61]. Advancing the field will require standardised, adaptive, and cross‑threat evaluation frameworks that mirror the dynamic nature of real‑world deployments.


## Discussion and Open Challenges

The rapid advancement of large language models has been paralleled by an equally dynamic threat landscape, yet the security community remains fragmented along isolated attack vectors rather than holistic resilience. This section synthesizes insights across prompt injection, data poisoning, and adversarial attacks to identify critical gaps and propose directions for future research.

#### Certified Defenses and the Poisoning Impasse

 Lorenz et al. observe that the first works on certified defenses with probabilistic guarantees underscore the profound difficulty of the problem, and multiple structural factors—such as the attacker's ability to influence many training points and the deep computational graph of training—make training-time certification far harder than inference-time certification [Lorenz_2024_Fullcert_7dbc4820]. In practice, poisoning attacks on LLM-based systems can exploit external knowledge sources; Wang et al. demonstrated that LLM agents can be backdoored via triggers injected into training data, enabling malicious operations when the trigger appears in the input or environment [Wang_2024_LLM_7c0f7746]. Li et al.'s AutoBackdoor framework further automates backdoor injection for LLMs, achieving over 90% attack success and revealing the inadequacy of current defenses [Li_2025_LLM_29a3a9ff]. Despite these risks, no end-to-end certified defense currently exists against the combined threat of training-time poisoning and inference-time exploitation. Closing this gap demands fundamental advances in training-time verification that scale to the compositional nature of modern LLM agents.

#### The Fragmentation of Benchmarks

Security evaluations today are largely compartmentalized: individual benchmarks assess jailbreaking, prompt injection, or backdoor resilience in isolation, failing to capture the multi-vector strategies that real-world adversaries employ. Tejedor et al. explicitly argue that ensuring robustness requires standardized evaluation benchmarks and threat models that cover jailbreaks, prompt injections, and data poisoning [Tejedor_2025_Elena_a76e13c1]. Meanwhile, agent-centric benchmarks including InjecAgent, AgentDojo, and Agent Security Bench evaluate indirect prompt injection, but they frequently lack realistic environments and remain partly private, which hinders reproducibility and the emergence of a unified risk perspective [Zhang_2025_AI_647785c1]. Indirect prompt injection in tool-integrated agents has been systematically benchmarked in suites such as InjecAgent and AgentDojo, confirming the severity of such risks [Jia_2025_LLM_604891e2]. A comprehensive benchmark that concurrently measures robustness against jailbreaking, prompt injection, data poisoning, and hallucination would enable researchers to detect cross-dimensional trade-offs, such as whether a defense that hardens against indirect injection inadvertently increases susceptibility to backdoor triggers. Realizing such a benchmark requires not only technical integration but also community-wide agreement on threat models and evaluation protocols, a standardization effort that has yet to materialize.

#### Multimodal Attack Surfaces

The expansion of LLMs to encompass visual, auditory, and embodied modalities dramatically enlarges the attack surface. Tejedor et al. caution that each additional modality introduces unique vulnerabilities that interact with textual threats [Tejedor_2025_Elena_a76e13c1]. Black et al. anticipate that multi-modal models and agentic systems will introduce new categories of misuse beyond those studied to date, raising concerns about the interconnectedness of tools where outputs from one model become inputs to another (the “daisy-chain” problem) [Black_2025_Open_488df73e]. They highlight that risk assessment of a single component is often insufficient to capture risks that emerge across the wider ecosystem [Black_2025_Open_488df73e]. In the embodied domain, BadVLA demonstrates that vision-language-action models are vulnerable to untargeted backdoors that cause widespread behavioral deviation [Zhou_2025_Badvla_37c2f4ff]. These findings underscore that developing safeguards at the fusion points of multimodal architectures is an urgent open challenge, and that certification must jointly consider all input modalities.

#### Securing Agentic Frameworks Against Cascading Failures

The shift from isolated chatbots to tool-using, multi-agent systems introduces qualitatively new failure modes where individually benign actions can combine into harmful outcomes. Li et al. provided a taxonomy of agent-specific attacks and demonstrated that exploiting memory, retrieval, and API components requires no sophisticated machine learning expertise [Li_2025_LLM_6131fb27]. Liu et al. showed that agentic AI coding editors can be manipulated to execute dangerous actions without user awareness, expanding the damage potential of prompt injection [Liu_2025_AI_ed04df60]. The most acute threat comes from multi-turn, indirect injection: Li et al.'s Sequential Tool Attack Chaining (STAC) demonstrated that individually harmless tool calls can be chained to perform collectively harmful actions, with attack success rates exceeding 90% against state-of-the-art agents, while even a reasoning-driven defense reduced success by at most 28.8% [Li_2025_LLM_c2206a72]. Yang et al. presented the first systematic investigation of backdoor attacks on LLM-based agents, revealing that triggers can be embedded not only in user queries but also in intermediate environment observations, and that even thought‑level manipulation can compromise intermediate reasoning steps while preserving the final output [Yang_2024_LLM_eba70536]. Wang et al. similarly demonstrated that LLM agents are vulnerable to backdoor attacks with exceptional stealthiness and that common fine‑tuning defenses provide only limited effectiveness [Wang_2024_LLM_7c0f7746]. Training-free defenses that rely on LLM-based detection prompts or static input-level encodings often use hand-engineered templates that are not adaptive to varying threat settings, limiting their effectiveness against dynamic multi-step attacks [Liu_2025_Aegis_6081be1b]. These findings collectively indicate that agentic security cannot rely on per‑query filters; it demands defenses that reason over entire action sequences and inter‑component trust relationships, potentially through runtime verification or policy enforcement that tracks the agent's planning process.

#### Transparency, White‑Box Access, and Ethical Disclosure

A persistent tension exists between the benefits of model transparency for auditing and the adversarial advantage conferred by white-box knowledge. The ethical implications of releasing attack tools are particularly acute. Das et al. emphasize that exposing system prompt extraction attacks and proposing defenses raises awareness and catalyzes further research on trustworthy LLMs [Das_2025_System_cda316c4]. Zhan et al. argue that revealing vulnerabilities through rigorous research is essential for building defenses and aligns with ethical principles, especially when the techniques are simple enough to be independently discovered by adversaries [Zhan_2025_LLM_ab9a7822]. Weng et al. emphasize that transparent research is necessary to develop better protections and that responsible disclosure enables AI developers to proactively address vulnerabilities [Weng_2025_LLMs_9f971db3]. Several works have explicitly framed their tools as defensive red-teaming instruments: AutoBackdoor is intended to identify and mitigate backdoor vulnerabilities [Li_2025_LLM_29a3a9ff], REDCODER is designed strictly for uncovering flaws in code generation models [Mo_2025_LLMs_eccb86af], and RAINBOWPLUS is released with guidelines encouraging ethical use and collaboration with developers [Dang_2025_Rainbowplus_b158c5a2]. Nonetheless, the community still lacks universally accepted guidelines for responsible disclosure of attack methodologies and exploitation code. Establishing norms analogous to responsible vulnerability disclosure in cybersecurity could mitigate dual‑use risks while enabling defensive progress, but formalizing such norms remains an unresolved governance gap.

#### Regulatory Standards and the Missing Temporal Dimension

A conspicuous absence in the current LLM security literature is the development or consideration of regulatory standards for deployment assurance. Existing works overwhelmingly concentrate on technical attack–defense dynamics without engaging with the formulation or enforcement of security requirements, leaving the field vulnerable to reactive, post‑incident regulation. Moreover, the dominant focus on point‑in‑time evaluations obscures the evolution of attacks over time: longitudinal studies that track how adversary strategies mutate in response to model updates, data shifts, or patching are virtually nonexistent. The aspirational goal of self‑healing models—LLM‑based systems that can autonomously detect, contain, and recover from adversarial manipulations—remains entirely unexplored. Addressing these deficits will require interdisciplinary collaboration spanning machine learning, systems security, and public policy, moving the community from reactive hardening toward proactive, certifiable, and continuously adaptive defense paradigms.

Taken together, the findings in this survey reveal a gradual convergence of attack taxonomies, yet defensive research remains siloed. One notable step toward integration is UniGuardian, which reframes prompt injection, backdoor attacks, and adversarial attacks as prompt-trigger attacks and introduces a single-forward detection pipeline capable of flagging all three in one pass [Lin_2025_Uniguardian_552288e3]. Extending such unified detection to multimodal and agentic deployments is an open challenge. Benchmark development faces similar fragmentation: Bhagwatkar et al. identified key flaws in popular agent-security benchmarks such as AgentDojo, Agent Security Bench, and InjecAgent, and released corrected versions alongside baselines [Bhagwatkar_2025_Indirect_2ccd3225]. This suggests that future evaluations should move toward adaptive, defense-aware attack protocols and ensure that novel frameworks are validated against corrected benchmarks, rather than inherited suites, before being adopted by practitioners.


## Conclusion

#### Synthesis of Threat Evolution

 Sandoval et al. (2025) reported a 31 % attack success rate on GPT‑3 series models in 2022, while adversarial fine‑tuning reduced this to near zero for smaller variants, though larger, more flexible models remained more vulnerable [Sandoval_2025_GPT_b45006a4]. Multi‑turn strategies that decompose malicious intent across conversational turns have emerged, exploiting the contextual reasoning of LLMs [Mo_2025_LLMs_eccb86af]. Automated red‑teaming frameworks have scaled attack diversity by orders of magnitude; RAINBOWPLUS, an evolutionary quality‑diversity search method, produced 100× more unique adversarial prompts than its predecessor and raised attack success rates to 95.55 % on Ministral‑8B [Dang_2025_Rainbowplus_b158c5a2]. Concurrently, backdoor injection has advanced from manual data poisoning to autonomous agent‑driven pipelines such as AUTOBACKDOOR [Li_2025_LLM_29a3a9ff]. As attacks grew more diverse and syntactically obfuscated, syntax‑based detection defenses proved unable to generalize, underscoring the need for adaptive protection [Wang_2025_Promptsleuth_c8e9516a].

#### The Defensive Arms Race

Early adversarial fine‑tuning treatments were shown to suppress rather than remove harmful capabilities, leaving models vulnerable to unseen jailbreaks [Sheshadri_2024_LLMs_ecd68cc1]. Today, defense approaches are broadly categorized into detection-based and prevention-based methods. Co‑evolutionary frameworks such as Aegis systematically evolve attackers and defenders together, achieving adaptive robustness against prompt injection [Liu_2025_Aegis_6081be1b]. PromptSleuth introduced a detection mechanism that maintains robustness across diverse and evasive attack variants, significantly lowering undetected attack rates while adding only modest overhead [Wang_2025_Promptsleuth_c8e9516a]. To address residual alignment weaknesses, SecureBreak provides a manually annotated dataset for building post‑generation filtering modules that act as a final guardrail, and can also guide alignment optimization [Arazzi_2026_Securebreak_0e3adcf7]. For jailbreaks, adaptive activation steering dynamically adjusts refusal strength based on input characteristics, overcoming the static limitations of prior approaches [Zhao_2025_LLM_45bb4e13]. At the frontier of robustness certification, Lorenz et al. (2024) introduced FullCert, a deterministic certifier against both data‑poisoning and evasion attacks, accompanied by formal convergence analysis and an open‑source toolset [Lorenz_2024_Fullcert_7dbc4820]. VeriGuard complements such certification by formally verifying agent policies against safety specifications, achieving near-zero attack success rates in benchmark evaluations [Miculicich_2025_LLM_fdef6034]. Adaptive attacks have circumvented every prompt-injection defense evaluated on LLM agents, confirming that no single technique is impregnable [Zhan_2025_LLM_ab9a7822].

#### The Critical Role of Benchmarks

Wahed et al. (2025) introduced MOCHA, a benchmark for assessing code LLMs against multi-turn malicious prompts, revealing high vulnerability to decomposed harmful intent [Wahed_2025_Mocha_c0ec2d2c]. Das et al. (2025) introduced SPE-LLM, a framework for systematically assessing system prompt extraction attacks, demonstrating that simple safety instructions are insufficient to prevent intellectual property leakage [Das_2025_System_cda316c4].

#### Practical Recommendations

For practitioners, three actionable principles emerge. First, implement defense-in-depth: no single mechanism suffices, so robust deployments should combine prevention, real-time detection, and post-generation filtering. Second, evaluate against adaptive, multi-turn attacks rather than static benchmarks alone. Third, demand verifiable safety claims through standardized scores, explicit threat models, and, where feasible, certification reports before integrating LLMs into safety-critical applications.

#### Toward a Secure LLM Ecosystem

The evolution of LLM safety research points toward certified robustness, exemplified by deterministic end-to-end frameworks such as FullCert [Lorenz_2024_Fullcert_7dbc4820]. Extending deterministic certification to the scale and multimodality of modern LLMs, integrating automated red‑teaming agents into continuous testing loops, and updating guardrails in real time will bridge the gap between static evaluation and dynamic threats. A secure LLM ecosystem will be built on comprehensive, verifiable safety engineering that keeps pace with rapid model advancement.

While much of the literature focuses on model-level attacks, the evaluation infrastructure itself has become an attack surface. Leaderboard maintainers have adopted complementary measures, including monitoring query distributions and community flagging mechanisms, to raise the cost of adversarial manipulation [Suri_2025_Exploiting_a50a2301]. Likewise, performance benchmarks establish realistic expectations for security-performance trade-offs in serverless ML deployments, enabling organizations to calibrate security controls to their risk profiles and performance requirements [Pathade_2026_AI_d9f29391]. Building on these practical lessons, alignment methods such as Safe RLHF still fall short for high-stakes contexts because they lack formal guarantees, and Seldonian probabilistic guarantees on constraint satisfaction offer a principled path toward stronger assurances [Chittepu_2025_Reinforcement_540113b3]. Together, these observations reinforce the central thesis that a secure LLM ecosystem depends not only on robust models but also on trustworthy evaluation and verifiable deployment practices.
